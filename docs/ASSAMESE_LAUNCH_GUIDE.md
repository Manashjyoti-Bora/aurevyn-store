# Nirvora: মালিকৰ বাস্তৱ launch আৰু দৈনিক কামৰ গাইড

## বৰ্তমানৰ সত্য অৱস্থা

Store-ৰ নাম Nirvora; GitHub repository-ৰ নাম এতিয়াও zenvora-store। নামটো
trademark বা domain-ত খালী বুলি পৰীক্ষা কৰা হোৱা নাই। Website-ত admin panel,
checkout, UPI QR, COD, manual supplier workflow আৰু queue-ৰ code আছে। এইবোৰ
বাস্তৱ account আৰু সম্পূৰ্ণ order দি পৰীক্ষা নকৰাকৈ 100% ready বুলি ক’ব নোৱাৰি।
লাখ-কোটি simultaneous visitor বা 24×7 চলাৰ নিশ্চয়তাও দিয়া সম্ভৱ নহয়।

Meesho-ৰ current price, stock, বিক্ৰী সংখ্যা বা return rate-ৰ live verified
feed এই code-ত নাই। সেয়ে system-এ স্বয়ংক্ৰিয়ভাৱে সৰ্বনিম্ন দাম, bestseller বা
lowest return বিচাৰি নিশ্চিত কৰি publish কৰিব নোৱাৰে। নতুন starter ideas
কেৱল draft, stock 0; আগতে live হোৱা products নিজে নিজে বদলোৱা নহয়।
প্ৰতিটো আগৰ live listing-ও যাচাই কৰিব লাগিব।

## Launch-ৰ আগতে আপুনি কৰিবলগীয়া কাম

1. Admin login কৰি Settings-ত আপোনাৰ প্রকৃত business নাম, ঠিকনা, support
   email/phone, shipping আৰু return policy পূৰণ কৰক। আইন আৰু কৰ সম্পৰ্কে CA
   আৰু payment provider-ৰ সৈতে কথা পাতক। GSTIN নাথাকিলে ভুৱা নম্বৰ নিদিব;
   GST registration লাগিব নে নাই আৰু inter-state/e-commerce নিয়ম আপোনাৰ
   ব্যৱসায়ৰ ক্ষেত্ৰত কি, CA-ৰ পৰা নিশ্চিত কৰক। GTIN আৰু GSTIN বেলেগ বস্তু।
2. Admin → Products-ত প্ৰতি product-ৰ **সঠিক Meesho link**, variant, গুণগত
   মান, stock, total cost, delivery আৰু return policy হাতে যাচাই কৰক। সঠিক
   বস্তু বুজোৱা ছবি ব্যৱহাৰৰ অনুমতি নিশ্চিত কৰক; AI render থাকিলে সেয়া
   illustrative বুলি স্পষ্ট কৰক, বাস্তৱ বস্তুৰ পৰা বেলেগ ছবি নিদিব। নিশ্চিত
   তথ্যৰ ভিত্তিত stock আৰু price দিয়ক; তাৰ পিছতহে publish কৰক। Existing
   products-ৰ বিষয়ে এই যাচাই বিশেষভাৱে প্ৰয়োজন।
3. Meesho-ত ব্যৱহাৰ কৰিব খোজা resale, delivery, COD, margin আৰু refund নিয়ম
   নিজ account-ত যাচাই কৰক। কেৱল নাম search কৰা মানে একে product নিশ্চিত
   নহয়। Exact listing আৰু variant মিলাওক।
4. Admin → Settings-ত যিবোৰ payment আৰু shipping পদ্ধতি বাস্তৱত পূৰণ কৰিব
   পাৰিব তাতেই enable কৰক। Support আৰু transactional email সত্যিকৈ পঠোৱা হয়
   নে পৰীক্ষা কৰক। Admin → Health আৰু Operations-ৰ errors চাওক।
5. নিজৰ এখন end-to-end test order দিয়ক: checkout, payment, Meesho placement,
   tracking, customer message, cancellation আৰু refund। Customer-ক notification
   যাব বুলি ধৰি নল’ব; inbox আৰু job log-ত পৰীক্ষা কৰক।

## Online payment, COD আৰু Meesho

UPI QR-ত customer-এ আপোনাৰ configured UPI ID-লৈ ধন দিয়ে। Customer-ৰ UTR বা
screenshot ধন পোৱাৰ প্ৰমাণ নহয়: bank statement-ত amount আৰু UTR মিলাই Admin →
Payments-ত confirm কৰক। Prepaid order-ত customer-ৰ পৰা delivery-ত আকৌ পইচা
ল’ব নালাগে। Meesho-ত পূৰ্ব-পরিশোধ কৰিলে supplier fail বা cancel কৰিলে refund
পাবলৈ অপেক্ষা কৰিবলগীয়া হ’ব পাৰে; cancellation/refund policy যাচাই কৰক,
নিজৰ working capital ৰাখক। Online payment পোৱা মানেই Meesho-ৰ order সুৰক্ষিত
বা নিশ্চিত নহয়। নিশ্চিত ব্যৱস্থা নোহোৱালৈ prepaid বন্ধ ৰাখিব পাৰে।

COD-ত কোনে ধন লয়, Meesho-এ margin আপোনাক কেনেকৈ দিয়ে, আৰু customer-ক কি
amount দেখুৱায়—প্ৰথমে নিজৰ account আৰু supplier terms-ত পৰীক্ষা কৰক। আপোনাৰ
website-ৰ COD বুলি ক’লেই margin স্বয়ংক্ৰিয়ভাৱে bank-ত আহিব বুলি কোনো নিশ্চয়তা
নাই। অসম্ভৱ বা অজানা হলে COD-ও বন্ধ ৰাখক। Refund নিয়ম গ্ৰাহকক আগতেই জনাওক।

পেছাদাৰী store-name payment-ৰ বাবে bank-ত merchant/current account আৰু UPI
merchant VPA বা approved payment gateway সম্পৰ্কে সোধক। Provider-এ KYC,
business proof বা GST তথ্য বিচাৰিব পাৰে। Admin-ত প্রকৃত VPA দিয়ক; secret, OTP
বা password chat বা repository-ত নিদিব। Gateway-ৰ automated verification এই
UPI QR workflow-ত আছে বুলি ধৰা নহ’ব।

## প্ৰতিদিনৰ order workflow

1. Admin → Orders আৰু Payments চাওক। UPI হ’লে bank-ত credit মিলাওক।
2. Supplier orders-ত purchase sheet চাওক; exact Meesho listing নিজে মিলাই
   customer-ৰ address আৰু সঠিক payment option দি order কৰক।
3. Supplier order ID আৰু উপলব্ধ courier/tracking তথ্য admin-ত দিয়ক। কেৱল
   order ID দিলেই Meesho status নিজে sync বা delivery নিশ্চিত নহয়।
4. Customer message, delay, cancellation আৰু refund নিজে নজৰ দিয়ক। Scheduled
   queue আৰু email-ৰ বাবে host, database, cron আৰু provider ঠিকমতে চলিব লাগিব।
   Browser voice control থাকিলেও ই সদায় চালু ফোন কল বা 24×7 alert নহয়। এই repository-ৰ Vercel cron দৈনিক এবাৰ (00:17 UTC), 24×7 continuous worker নহয়।

## পৰৱৰ্তী উন্নতি

Supplier অনুমোদনসহ verified product feed, exact listing links আৰু freshness
checks; bank/gateway verified payment webhook; পৃথক worker ও monitoring;
order alert আৰু delivery provider integration; mobile browser, accessibility,
load আৰু real-payment testing। Free open-source software থাকিলেও hosting,
messages, LLM API বা scale সদায় বিনামূলীয়া নহয়। কোনোটো third-party tool-লৈ
customer address পঠোৱাৰ আগতে privacy আৰু provider terms যাচাই কৰক।
