# Aurevyn — V4/V5 blueprint conformance

This file answers one question honestly: **how much of the two attached
blueprints — `JARVIS_CONSOLIDATED_BLUEPRINT_V4-1` and `VYRANTE + JARVIS
MASTER SYSTEM BLUEPRINT V5.0` — is actually built in this repository?**

A blueprint section that describes good practice is not evidence that the
practice exists. Status is claimed only where code or a stored record exists,
and every “Live” row names the file that implements it. The earlier V2/V3 audit
is in [`JARVIS_BLUEPRINT_STATUS.md`](JARVIS_BLUEPRINT_STATUS.md); this document
covers only what the two newer documents add or restate.

Legend — **Live** (implemented and tested), **Partial** (real implementation,
named gap), **Blocked** (needs the owner or a provider), **Not built**,
**Deliberately absent** (the blueprint allows it; this store chose not to).

## 4. Where this repo deliberately departs from the blueprint

1. **One Next.js app instead of a monorepo + Python service.** The blueprint
   itself says to adapt structure to the existing repository rather than move
   files blindly. A second runtime would add deployment and secret-management
   surface without adding a capability the store currently uses.
2. **No voice surface.** Voice is an input method, not authentication; the
   blueprint's own safety rules make the button + evidence path sufficient.
3. **No model-routed autonomy.** Without a provider key and a spend cap, agents
   reason deterministically over records. This keeps every number reproducible
   and every claim auditable.
4. **No Meesho connector, by rule.** Supplier ordering stays a manual owner
   action, and the store records that as an owner attestation.

## 5. What only the owner can unblock

| Item                                | Why the repo cannot do it                                                                                          |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| UPI VPA + one verified test payment | Requires the owner's bank/UPI identity; `/api/health` reports `paymentsProvider: "NONE"` until then.               |
| LLM provider key (optional)         | Secret, owner-funded; without it agents stay deterministic.                                                        |
| Backup/restore rehearsal            | Must be performed against the real Neon project and timed.                                                         |
| Search Console / Bing verification  | Requires the live domain and owner account.                                                                        |
| Real catalogue                      | 12 demo products remain; listing real supplier products is the owner's sourcing decision.                          |
| Cron scheduler + `CRON_SECRET`      | Must be set in the hosting environment; otherwise retention, jobs and team cycles only run when a route is called. |

## 6. অসমীয়াত সাৰাংশ

- এই পাছটোত blueprint V4/V5 ৰ **data retention** অংশটো ৰূপায়ণ কৰা হৈছে: `error_logs` ৩০ দিন, `api_logs` ৩০ দিন, webhook ১৮০ দিন, resolved support message ১৮০ দিন, team cycle ৯০ দিন, audit log ২ বছৰ। অৰ্ডাৰ, payment, refund, shipment, supplier order — **কেতিয়াও** মচা নহয়, কাৰণ সেইবোৰ হৈছে হিচাপ আৰু গ্ৰাহক সুৰক্ষাৰ প্ৰমাণ।
- দিনে এবাৰ `/api/cron/jobs` ৰ সৈতে sweep চলে; সুকীয়াকৈ `/api/cron/retention`-ও আছে (`CRON_SECRET` লাগে)। বিস্তারিত: `docs/PRIVACY_RETENTION.md`।
- V5 ৰ Python Jarvis runtime, ভইচ, MFA, model-routed agent, creative pipeline, `/api/v1` — এইবোৰ **এতিয়াও নাই**, আৰু এই ডকুমেণ্টত সেইদৰেই লিখা আছে। যি আছে তাৰ file উল্লেখ দিয়া আছে; যি নাই তাৰ কাৰণো।
- ব্ৰেণ্ডৰ নাম: blueprint ত **VYRANTE** লিখা আছে, কিন্তু এই ৰিপ’জৰ্টত **Aurevyn** আছে। নাম সলোৱাটো আপুনি ক’লেহে কৰিম — নিজে সলনি নকৰোঁ।
